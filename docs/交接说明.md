# 固收工作台 · 交接说明（给后续维护者 / 其他模型）

> 目标：任何人（或任何 AI 模型）拿到这个目录后，能在 10 分钟内知道**东西在哪、怎么跑、怎么加工具、怎么重新打包**。
> 最后更新：2026-11-03（新增「报价要素生成」，右侧改为「运行中 + 更多工具」；Windows 验证通过；macOS 待真机验收）。
>
> **说明**：本仓库是 macOS 发行版源码快照。`build/`、`tests/`、`AGENTS.md` 属于开发仓库，不在这里；本文提到的打包/测试命令需要在完整开发目录中执行。

## 1. 这是什么

一个**纯本地**的启动台，把十二个既有工具收进同一个入口：

| 投标簿记提取 | `../bidbook_tool` | FastAPI + 自定义页面 | 8765 |
| 报价要素生成 | `../bidbook_tool` | FastAPI + 自定义页面 | 8766 |
| WACC 批量计算 | `../wacc-tool` | Streamlit | 8512 |
| 上市要素整理 | `../上市要素整理` | 标准库 http.server | 8513 |
| 交易要素提取 | `../固收工具箱` | 标准库 http.server | 8520 |
| 债券计算器 | `../固收工具箱` | 标准库 http.server | 8514 |
| 回购/资金计算器 | `../固收工具箱` | 标准库 http.server | 8515 |
| 现金流/付息日历 | `../固收工具箱` | 标准库 http.server | 8516 |
| 组合风险快照 | `../固收工具箱` | 标准库 http.server | 8517 |
| 国债期货基差 | `../固收工具箱` | 标准库 http.server | 8518 |
| 投标/中标统计 | `../固收工具箱` | 标准库 http.server | 8519 |

工作台本体只做四件事：**启动/停止子进程、单实例、环境自举、跳转**。它**不碰**十二个工具的业务代码，也不打通它们之间的数据。

- 左侧主列表只放 6 个常用工具；其余工具由 `tools.json` 的 `"primary": false` 标记，收进右侧「更多工具」。
- 右侧上半「运行中」集中显示已启动的工具；次级工具启动后会从「更多工具」移到「运行中」，停止后回到「更多工具」。
- 报价要素生成与投标簿记提取共用 `../bidbook_tool` 目录和 `bidbook` 环境，只新增 `quote_line.py` 与 `quoteline/`，不改投标簿记的既有代码。

- 只监听 `127.0.0.1`，校验 `Host` / `Origin`。
- 运行期**零网络**：依赖全部来自本地 wheelhouse，Python 来自包内归档。
- 工作台本体**只用 Python 标准库**；前端无框架、无 CDN、无网络字体。

## 3. 一条请求/一次启动发生了什么

```
双击 .command
  → bash：xattr/chmod 自愈
  → 若包内只有 tar.gz：/usr/bin/tar --strip-components=1 解到 runtime/python/<stem>
  → 逐个候选验证 python ≥ 3.10
  → exec python start.py
       → load_config(tools.json)
       → acquire_launch_lock（并发双击只放一个进来）
       → find_running（lock + /api/ping 复验；命中就开浏览器返回）
       → pick_free_port（8787 起，顺延 20 个）
       → Bootstrapper / ToolManager / adopt_orphans()
       → 注册 atexit + SIGTERM/SIGHUP → manager.shutdown()
       → write_lock(runtime, pid, port)
       → ensure_all_async()（后台建 venv + 装 wheel，不挡首屏）
       → 桌面快捷方式（mac 首次）
       → server.run_workbench()（阻塞）
       → /api/shutdown 或 Ctrl-C/SIGTERM → 停全部子进程 + finally 清锁
```

浏览器 → `GET /api/state`（每 2 秒）→ 卡片状态；点「启动」→ `POST /api/tools/<id>/start` → ToolManager 起子进程 → 轮询健康地址 → `running`。

**归属模型**：`self`（本次启动）/ `orphan`（上次残留，可停）/ `external`（不是我们起的，拒绝停止）。
**归属判断**：`pids.json` + 端口健康 + 锁复验；不要只凭端口上“有服务”就认领。

## 4. `tools.json` 配置契约

```jsonc
{
  "version": 1,
  "workbench": { "port": 8787 },
  "platform": {
    "darwin": { "pythonArchive": "runtime/python/cpython-...tar.gz" },
    "win32":  { "pythonArchive": null }
  },
  "environments": {
    "streamlit": {
      "requirements": { "darwin": "requirements/streamlit-mac.txt", "win32": "requirements/streamlit-win.txt" },
      "wheelhouse":  { "darwin": "runtime/wheels/macos-arm64-cp312", "win32": "runtime/wheels/win-amd64-cp311" },
      "probe": ["streamlit", "pandas", "openpyxl"]
    }
  },
  "tools": [
    {
      "id": "bondtable", "name": "境内债制表", "desc": "...",
      "root": "../境内债制表工具",           // 相对工作台根目录
      "kind": "streamlit",                  // streamlit | python-entry
      "entry": "scripts/app.py",            // 相对 root
      "args": ["--port", "{port}"],         // 可选；{port} 会被替换
      "environment": "streamlit",           // 必须已定义
      "port": 8511,
      "healthPath": "/_stcore/health",      // 必须以 / 开头
      "dirs": { "输出": "data/输出" },       // 可选；key 含“输出”用于最近产物
      "primary": true                       // 可选，默认 true；false 收进「更多工具」
    }
  ]
}
```

约定：

- `kind=streamlit` 时由工作台拼 `python -m streamlit run <entry> --server.address 127.0.0.1 --server.port … --server.headless true`。
- `kind=python-entry` 时直接 `python <entry> [args]`。
- `healthPath` 用工具真实健康地址；bidbook / quoteline 没有专用健康路由，用 `/`。
- `dirs` 里 key 含「输出」的目录会用于「最近产物」。
- `primary` 只影响前端展示：`true`（默认）进左侧主列表，`false` 进右侧「更多工具」。`tools` 数组顺序就是渲染顺序。
- 同一个 `root` 可以被多个工具复用（如 `../bidbook_tool` 下的 `app.py` 与 `quote_line.py`），打包时只会复制一次目录。

## 5. 新增一个工具（清单式）

假设新工具目录叫 `../new-tool`，入口 `app.py`（FastAPI），依赖 `pandas`：

1. **放目录**：把工具完整放到与工作台同级的 `Work/new-tool/`，不要改它的业务代码。
2. **建环境**（若依赖与现有环境不同）：
   - 新建 `requirements/newtool-mac.txt`（macOS 用）与 `requirements/newtool-win.txt`（Windows 验证用，可不建）。
   - 在 `tools.json.environments` 里加：
     `"newtool": {"requirements": {"darwin": "...-mac.txt", "win32": "...-win.txt"}, "wheelhouse": {...}, "probe": ["pandas"]}`
   - 抓 wheel（构建期联网，只走镜像）：
     ```powershell
     py -3.11 build/build_wheels.py --requirements requirements/newtool-mac.txt `
       --out runtime/wheels/macos-arm64-cp312 `
       --platform macosx_11_0_arm64 --python-version 3.12 --abi cp312
     ```
   - 校验闭包：`build/verify_bundle.py ...` 必须输出 `OK`。
3. **登记工具**：在 `tools.json.tools` 里加一条（id/name/desc/root/kind/entry/environment/port/healthPath/dirs/primary），数组顺序就是页面顺序。
4. **测试**：
   - `tests/` 加一条 manager 级别的启动/停止（可复用 `tests/fixtures/dummy_tool.py` 的模式）；
   - `scripts/acceptance/` 加该工具的输入矩阵（参考现有三份脚本）。
5. **前端**：主列表/右栏由 `/api/state` 驱动，无需改代码；常用工具保持默认 `primary`，较少用的加 `"primary": false`。如需特殊展示，改 `workbench/web/app.js` 的 `displayName`/状态文案。
6. **打包**：`py -3.11 build/stage.py --platform darwin` 会自动带上 `tools.json` 里 `root` 指向的目录；确认 `dist/` 新 zip 里出现该目录。
7. **验收**：`py -3.11 scripts/selftest.py --tool <id>`，以及 `py -3.11 -m unittest discover`。

> 不要：把依赖装进工具的 `.venv`、在运行期 pip install、把模型/数据下载放到首次运行。

## 6. 如果以后要接“模型”（LLM / OCR / 本地推理）

当前十二个工具**没有任何在线模型调用**。若未来某个工具要加模型：

- **权重/模型文件放工具自己的目录**（例如 `new-tool/models/`），随包分发；不要放 `runtime/`（会被当成可重建缓存删掉）。
- **严禁运行期下载**：`build/stage.py` 已排除 `data/`、`.venv*`、`node_modules`、`logs`，但**不会**自动排除 `models/`；如果模型很大，请在 `stage.py` 的 `SKIP_DIRS`/复制逻辑里显式处理，或单独放 `runtime/models/` 并在文档里写明「不可删」。
- **通过环境变量传路径**：工作台启动子进程时会带 `PYTHONUTF8=1` 等；如需模型路径，在 `manager._spawn` 里加（注意别写死绝对路径）。
- **离线校验**：在 `verify_bundle.py` 之外加一条「模型文件存在 + 校验和」检查，或在 `diagnostics.build_report` 里加模型版本。
- 如果是**让 AI 模型维护这个仓库**：先读 `AGENTS.md`，再按本文件第 9 节的命令跑测试；不要改 `../` 下十二个工具的业务代码。

## 10. 常见故障速查

| 现象 | 先看 | 处理 |
|---|---|---|
| 双击没反应 | `.command` 是否有执行位/被隔离 | 右键→打开；或 `bash 启动工作台.command` |
| 环境装不上（`No pyvenv.cfg file` / 106） | 是否 Store 版 Python | 工作台会自动改用 `%USERPROFILE%`；也可设 `WB_RUNTIME_DIR` |
| 页面打不开 | `runtime/logs/start.log`、`bootstrap-*.log` | 先用 `诊断报告.command` |
| 端口被占 | 卡片显示的实际端口 | 自动顺延；全部占满会明确报错 |
| 卡片显示「上次残留」 | `pids.json` | 点「停止」清理；不要手工杀工作台 |
| 环境想重来 | `<runtime>/envs/<id>` | 删掉后重启，或页面里点「重建」 |
| 想彻底重置 | `<runtime>` | 退出工作台后整目录删除 |

日志位置：
- 启动：`<runtime>/logs/start.log`
- 环境安装：`<runtime>/logs/bootstrap-<env>.log`
- 工具输出：`<runtime>/logs/<tool_id>.log`

## 12. 不可违反的约定

- 运行期**零网络**；依赖只从本地 wheelhouse 安装，Python 来自包内。
- 只绑 `127.0.0.1`；`Host`/`Origin` 必须校验。
- **不改**十二个工具的业务代码；只用子进程调用。
- 所有文件读写显式 `encoding="utf-8"`；子进程参数用 list，不拼 shell。
- 工作台本体只用标准库；前端不引 CDN/网络字体。
- 端口：8787 / 8511 / 8765 / 8766 / 8512 / 8513 / 8520，被占顺延最多 20 个。
- 交付包只保留目标平台内容；mac 包里不出现 `.bat` / win 轮子 / win requirements。

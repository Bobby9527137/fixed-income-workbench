# 竞品观察与改进记录

> 2026-10-28。目标不是“做一个更花哨的壳”，而是在**离线、单人、三固定工具**的前提下，把成熟产品里真正有用的交互借过来。

## 一、看了哪些成品

| 产品 | 定位 | 值得借的点 |
|---|---|---|
| **Pinokio**（8.3k★，AI Browser） | 一键安装/启动任意开源 AI 项目 | 每个应用独立目录 + 独立 venv；安装脚本可审计；Discover 只放审核过的脚本；运行日志/任务栏可见 |
| **Stability Matrix**（9k★，SD 包管理器） | 多版本 WebUI 的安装、更新、启动 | 一键安装/更新；“内嵌 Python/Git，无需全局安装”；**数据目录可整体搬走**；共享模型目录；启动参数/环境变量编辑器；终端日志 |
| **Portainer / Homepage / Dashy** | 容器/服务仪表盘 | 卡片式状态、批量启停、单服务日志、端口可见；状态汇总 |
| **ComfyUI Manager** | 自定义节点/依赖管理 | “缺什么补什么”、一键修复、安装失败可见原因 |
| **LM Studio / Jan** | 本地模型管理 | 硬件/环境自检、模型目录清晰、离线优先 |

共同规律：**用户不想看终端**。好的启动器都把“装环境、起服务、看日志、找文件”收进同一页，并且**失败原因必须可读**。

## 二、本工作台已有的差异化

- 三个工具都是**现成项目**，工作台不改它们代码，只做进程/环境外壳。
- **完全离线**：内置 Python + 本地 wheelhouse，运行期零网络。
- **中文路径/空格**、macOS Gatekeeper、单实例、孤儿接管这些“国内办公现场”问题处理得比通用工具细。
- 只绑 `127.0.0.1`，Host/Origin 校验，无账户体系。

## 三、这一轮采纳并落地的改进

| 改进 | 来源 | 实现 |
|---|---|---|
| 顶部**状态汇总**（`3/3 运行 · 环境 2/2 · PID · 端口`） | Portainer/Homepage | `/api/state` 前端计算 |
| **全部启动 / 全部停止** | Portainer/Homepage | 复用 `start-all` / `stop-all`，串行避免抢 CPU |
| 卡片新增**日志 / 目录**次级按钮 | Stability Matrix / Pinokio | 日志弹窗；目录直接调系统文件管理器 |
| **在 Finder 中定位**（目录、日志、单个产物） | Stability Matrix 的文件管理 | 新增 `POST /api/tools/<id>/reveal`，白名单校验后 `open` / `explorer` / `xdg-open` |
| **最近产物按工具分组** | Stability Matrix | `/api/files/recent` 增加 `by_tool`，保留旧字段兼容 |
| **环境一键重建**（仅出错时出现） | ComfyUI Manager | 复用 `/api/envs/<id>/rebuild`，顺序重建 |
| **桌面直达快捷方式** | Pinokio 的“装完即用” | 首次启动在 `~/Desktop` 生成包装脚本 |

这些都没有引入新依赖，仍满足“标准库 + 离线”。

## 四、刻意没做的（附理由）

| 功能 | 为什么不做 |
|---|---|
| 应用市场 / 在线安装脚本 | 交付物是固定三个工具，运行期零网络；引入市场等于引入审计与供应链风险 |
| 自动更新（联网） | 同上；未来可做“U 盘离线升级包”，但需要签名与回滚设计 |
| 启动参数/环境变量编辑器 | 三个工具的启动参数由工作台统一生成，暴露给最终用户只会增加误配置 |
| 资源占用曲线 / GPU 监控 | 目标场景是办公机跑轻量工具，收益低；诊断报告已含端口/进程/日志 |
| 菜单栏常驻 App | 需要额外打包（py2app/Tauri）并处理签名；当前 `.command` + 浏览器足够 |
| 内嵌 iframe | 已在上一轮移除：Streamlit 的 WebSocket/剪贴板在 iframe 里不稳定 |

## 五、下一步优先级（建议）

**P1（低成本、高收益）**
1. 失败时 macOS 通知（`osascript display notification`），用户不用盯终端。
2. 首次启动前检查磁盘剩余空间 + macOS 版本/架构，提前给出人话提示。
3. 诊断报告一键复制路径/打包成 zip（现在只有一个 txt）。

**P2（需要设计）**
4. 离线升级包：`升级包.zip` + 版本号 + 校验和，替换代码但保留 `runtime/envs`。
5. 工具级健康页：每个工具自己的依赖/模型版本（需要工具暴露版本号）。
6. 日志实时滚动（现在是一次性 tail），用 SSE 或轮询增量。

**P3（不做也行）**
7. 菜单栏常驻/开机自启。
8. 多用户/远程访问（与“只绑本机”的安全模型冲突）。

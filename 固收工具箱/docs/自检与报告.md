# 自检与问题报告

## 自检会检查什么

每个工具的「🩺 自检」会依次检查：

1. Python 版本 ≥ 3.10；
2. `openpyxl` 能否导入；
3. 报告目录是否可写（不可写会尝试创建）；
4. 字段定义是否合法（key 不重复、默认值在选项内、表格列类型正确）；
5. 随机示例能否完整跑通（生成 → 校验 → 计算）。

工作台的「自检」还会检查：

- `tools.json` 是否加载、工具目录和入口是否存在；
- 运行目录 `logs / envs / reports` 是否可写；
- 四套环境（streamlit / bidbook / stdlib / toolbox）是否就绪；
- 工作台锁、启动锁是否为残留；
- 每个工具的端口是否可用或被占用。

## 能自动修的

- 创建缺失的运行目录；
- 清理 pid 已死的工作台锁；
- 清理超过 15 分钟的启动锁；
- 重新认领/剔除上次残留的工具进程记录。

## 修不了怎么办

会生成一份 Markdown 报告，默认在：

```
~/固收工作台报告/<工具>-bug-YYYYMMDD-HHMMSS.md
```

报告包含：工具/版本/时间、系统与 Python、自检结果、错误堆栈、示例输入、复现步骤。

**报告只保存在本机，不会自动发送。** 页面会显示路径和「下载报告」；你确认无误后，再决定是否转发给维护者。

## 工作台报告

工作台自检失败时，报告在：

```
<runtime>/reports/workbench-selfcheck-YYYYMMDD-HHMMSS.md
```

`<runtime>` 在 macOS 是 `~/Library/Application Support/固收工作台/runtime`。
